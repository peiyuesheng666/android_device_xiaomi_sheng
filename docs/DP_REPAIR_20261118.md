# DP 外接显示错误路径修复（2026-11-18）

本次仅修改设备树内编译的显示 HAL 源码。没有实机 DP 故障日志，
不能判定以下缺陷就是群友反馈的根因，也未宣称外接显示已恢复。

## 已修复

- `core/display_pluggable.cpp`：`HWEventsInterface::Create` 失败后，
  `DisplayBase::Deinit()` 已负责销毁硬件接口，原路径再次调用
  `HWInterface::Destroy()`，造成重复释放。现在清理后直接返回原错误，
  同时避免继续运行颜色模式初始化。
- `dal/hw_tv_drm.cpp`：外接分辨率覆盖配置改用无异常的严格数值解析，
  支持 `width:height:fps[:format]`。拒绝空字段、负数、零时序、溢出、
  非数字和额外字段，保持输出索引不变。未找到时序时返回
  `kErrorNotSupported`，避免把默认索引误当成请求的模式。
  可选 format 数值保留原有兼容行为，不参与时序匹配。

## 本地验证

在项目根目录运行 `wsl -e python3 scripts/test_sheng_dp_host.py`，结果 PASS。
测试直接提取并编译实际 `GetConfigIndex` 和 `DisplayPluggable::Init` 函数，
用模拟硬件接口注入事件初始化失败，验证只清理一次且不再初始化颜色模式；
同时覆盖成功初始化、有效时序、可选 format、无匹配、空模式列表、空指针、
坏字段和整数溢出。编译开启 `-fno-exceptions`、AddressSanitizer、
UndefinedBehaviorSanitizer 和 `-Wall -Wextra -Werror`。

这属于主机故障注入测试，不模拟 USB-C PD/Alt Mode、PS5169 电气行为、
AUX 传输或链路训练。尚未运行完整 Android 编译，也未生成或刷入新镜像。
两处文件已位于现有显示 HAL 的 Android.bp 编译源列表中。

## 仍需确认

需要故障版本和接屏时的内核日志、logcat 才能进一步区分：
Type-C 协商/中继器、内核 DP 注册或链路训练、DRM 热插拔、显示 HAL。
仓库中旧的 DP AUX 生命周期报告只针对历史内核初始化失败，不能据此
推定当前 ROM 的故障源自相同问题。
